# Washington Sales Tax Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collect WA sales tax (admin-editable rate, launching 8.9%) on class-booking and firing checkouts, itemized on the payment forms, computed after coupon discounts, stored per transaction.

**Architecture:** One pure `computeTotals` function shared by server services and client forms (identical integer math, so displayed = charged by construction). Rate lives on Site Settings. `taxCents` is persisted on bookings, firing-requests, and payments for DOR reporting. One migration covers the four new columns.

**Tech Stack:** Payload 3.85, Next.js 16, Square Payments (amount-only charge — no Orders API), vitest.

**Spec:** `docs/superpowers/specs/2026-08-17-sales-tax-design.md`

## Global Constraints

- All money math in integer cents. `taxCents = Math.round((taxableCents * rate) / 100)` — round half-up, once, on the transaction taxable amount.
- Coupon discount reduces the taxable amount FIRST: `taxable = max(0, subtotal − discount)`; `total = taxable + tax`.
- Rate source: `SiteSettings.salesTaxPercent`; unset/invalid/≤0 ⇒ rate 0 ⇒ behavior byte-identical to pre-change (this is the graceful-degrade AND the legacy-test baseline).
- `amountCents` on bookings/firing-requests/payments = total actually charged (now tax-inclusive). New `taxCents` on all three, default 0. Historical rows stay 0 — correct.
- $0-total flow (100% coupon) unchanged: no sourceId required, no charge, tax 0.
- **Test-suite determinism (hard requirement):** the test DB's site-settings row will get 8.9 backfilled by push. Every spec file that asserts charge amounts MUST pin the rate: legacy files pin 0 in a `beforeAll`; new tax cases set 8.9 inside try/finally that resets to 0. Never leave a non-zero rate behind (cross-file pollution lesson).
- Commit messages conventional, NO AI attribution. `pnpm`. Deploy: dev droplet first with sandbox-card verification; prod ONLY on Brian's explicit go (charge-amount change).

- [ ] **Step 3: Write `src/lib/tax.ts`**

```ts
import type { Payload } from 'payload'

/**
 * Sales-tax math shared by the server (authoritative charge) and the payment
 * forms (display). One pure function, integer cents throughout — the number
 * the customer sees is the number the card is charged, by construction.
 * WA treatment: seller-funded coupons reduce the taxable price, so tax is
 * computed on (subtotal − discount).
 */

export interface TotalsInput {
  subtotalCents: number
  discountCents: number
  /** e.g. 8.9 — from Site Settings. 0 (or invalid) disables tax. */
  taxRatePercent: number
}

export interface Totals {
  taxableCents: number
  taxCents: number
  totalCents: number
}

export function computeTotals({ subtotalCents, discountCents, taxRatePercent }: TotalsInput): Totals {
  const taxableCents = Math.max(0, Math.round(subtotalCents) - Math.round(discountCents))
  const rate = Number.isFinite(taxRatePercent) && taxRatePercent > 0 ? taxRatePercent : 0
  const taxCents = Math.round((taxableCents * rate) / 100)
  return { taxableCents, taxCents, totalCents: taxableCents + taxCents }
}

/** Current checkout tax rate from Site Settings; 0 when unset (never throws). */
export async function getSalesTaxPercent(payload: Payload): Promise<number> {
  const settings = await payload.findGlobal({ slug: 'site-settings', depth: 0 })
  const rate = (settings as { salesTaxPercent?: number | null }).salesTaxPercent
  return typeof rate === 'number' && Number.isFinite(rate) && rate > 0 ? rate : 0
}
```
